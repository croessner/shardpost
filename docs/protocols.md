# Protocols, features and RFCs

This document lists, protocol by protocol, what ShardPost implements:
the standards it follows, the extensions it advertises, the commands
and methods it answers, and where it deliberately or knowingly deviates.
It describes **ShardPost 0.36.0** as of 2026-10-01 and was written from
the code, not from earlier documentation.

How to read the tables:

| Mark | Meaning |
|---|---|
| ✅ | Implemented and advertised |
| ◐ | Implemented with a documented restriction or deviation (see the note) |
| ✗ | Not implemented |
| ⚙ | Only present when the named setting is configured |

An RFC listed here means that ShardPost implements the parts named in
the row, not that every SHOULD of that RFC has been verified. Test
evidence is in [Quality](development/quality.md) and the versioned
[conformance results](../hack/conformance.md).

## Overview

| Protocol | Role | Listener (config key) | Container default | Service port | TLS | Main standards |
|---|---|---|---|---|---|---|
| IMAP | Mailbox access | `server.imap_addr` | `:1143` | 143 | STARTTLS | RFC 9051, RFC 3501 |
| IMAPS | Mailbox access | `server.imaps_addr` | `:1993` | 993 | implicit ⚙ certificate | RFC 8314 |
| POP3 | Mailbox access (INBOX) | `server.pop3_addr` | `:1110` | 110 | STLS | RFC 1939 |
| POP3S | Mailbox access (INBOX) | `server.pop3s_addr` | `:1995` | 995 | implicit ⚙ certificate | RFC 8314 |
| LMTP | Delivery from the MTA | `server.lmtp_addr` | `:2424` | 24 | STARTTLS | RFC 2033 |
| ManageSieve | Sieve script management | `sieve.addr` | `:14190` | 4190 | STARTTLS | RFC 5804 |
| JMAP | Mailbox access over HTTP | `jmap.addr` | off | 9443 (overlay) | HTTPS | RFC 8620, RFC 8621 |
| Admin API | Operations | `admin.socket` / `admin.addr` | off | 8443 (component) | Unix socket / mTLS | OpenAPI 3.0.3 |
| HTTP | Metrics and health | `server.http_addr` | `:8080` | — | none | Prometheus |

The server does **not** accept internet SMTP and has no submission
listener (587/465): an upstream MTA delivers through LMTP, and outgoing
mail generated by the server goes to a configured relay
([Outbound SMTP](#outbound-smtp)).

Every mail and JMAP listener accepts the HAProxy PROXY protocol from
trusted networks; see [Transport](#transport-tls-proxy-protocol-listeners).

## IMAP

Parser, dispatcher and encoder are ShardPost's own code
(`internal/imapproto`). The vendored go-imap v2 is used only for MIME
section extraction, BODYSTRUCTURE and LIST pattern matching.

### Capabilities

The capability list depends on the session state. Before login the
server advertises the first group and the authentication capabilities;
after login it adds the rest. The list is sent in the greeting and in
the tagged OK of LOGIN/AUTHENTICATE.

Before login, any command other than the not-authenticated ones gets
`NO Please authenticate first`; a `UID` prefix on a command that has
no UID form is `BAD`. Pending changes are polled before every command
in the selected state; `FETCH`, `STORE` and `SEARCH` without
`UID` hold back expunge responses as RFC 9051 §7.5.1 requires.

### SEARCH, SORT and THREAD

| Area | Supported |
|---|---|
| Flag keys | `ALL ANSWERED DELETED DRAFT FLAGGED SEEN` and their `UN…` forms, `NEW RECENT OLD`, `KEYWORD`, `UNKEYWORD` |
| Date keys | `BEFORE ON SINCE` (internal date), `SENTBEFORE SENTON SENTSINCE`, `SAVEDBEFORE SAVEDON SAVEDSINCE SAVEDATESUPPORTED` (RFC 8514), `YOUNGER OLDER` (RFC 5032) |
| Size keys | `LARGER SMALLER` |
| Set keys | sequence sets, `UID <set>`, `$` (RFC 5182) |
| Object keys | `MODSEQ` (RFC 7162), `EMAILID`, `THREADID` (RFC 8474) |
| Text keys | `FROM TO CC BCC SUBJECT BODY TEXT HEADER` |
| Logic | `NOT`, `OR`, parentheses |
| Charset | UTF-8, US-ASCII and every charset in the WHATWG list; unknown charsets get `[BADCHARSET (UTF-8)]`. After `ENABLE UTF8=ACCEPT` only UTF-8 and US-ASCII (anything else is `BAD`). |
| Result forms | classic `SEARCH`, `ESEARCH` with `RETURN (MIN MAX ALL COUNT SAVE)`; always `ESEARCH` after `ENABLE IMAP4rev2` |
| SORT keys | `ARRIVAL CC DATE FROM REVERSE SIZE SUBJECT TO DISPLAYFROM DISPLAYTO` |
| THREAD | `REFERENCES`, `ORDEREDSUBJECT` |

Text keys match substrings, without regard to case, as RFC 3501 and
RFC 9051 specify, against the decoded message: header names and values
(encoded words decoded, raw 8-bit text in `fts.fallback_charset`) and
the body as the text of its `text/*` parts converted to UTF-8 (HTML
reduced to its visible text), the file names of all parts and the
header and text of attached messages. `TEXT` matches the header or the
body, `HEADER <name> <value>` the field value. The full-text index
([FTS](#full-text-search)) supplies candidates — never fewer than the
messages that match — for the header and the body of every key,
wherever it is in the tree (`AND` intersects, `OR` unites, `NOT` does
not narrow). Each candidate is checked: headers against the decoded
header the index keeps per message, the body by reading the message
only where the body candidates include it, `fts.verify_parallel`
(default 8) messages at a time under the memory budget. A value that
may begin inside a header word (`TEXT`, `HEADER` with names other than
Subject and the address fields) checks the stored header of every
message of the mailbox; a key with no word the index can narrow by (one
or two letters inside a word) reads every message. A message expunged
during the search is no match; if a message cannot be read for another
reason, the command fails with `NO [SERVERBUG]` instead of returning a
partial result. A search whose client closes the connection stops
checking messages, and the session ends without an answer. With
`fts.imap_search: word` (default `substring`) the index answers
`SUBJECT`, `BODY`, `TEXT` and `HEADER Subject` alone, by word (all words in any order, stem, part of a word), without reading
messages. An account whose index lacks the version marker (indexed
before this release, or a rebuild that has not completed) does not use
the index and checks every message until `fts_rebuild` has run.

Not supported: `FUZZY` (RFC 6203), `CONTEXT=SEARCH`/`CONTEXT=SORT` (RFC 5267), `ESORT`,
`PARTIAL` (RFC 9394), `MULTISEARCH` (RFC 7377).

### ACL

RFC 4314 with the rights `l r s w i p k x t e a`. The obsolete `c` maps
to `k` and `d` to `x t e`.

| Feature | Status | Notes |
|---|---|---|
| `SETACL` with `+`/`-`, `DELETEACL` | ✅ | Need `a`. Both record a share notification for the grantee (RFC 9670 §3; not for `anyone`). |
| `GETACL`, `LISTRIGHTS` | ✅ | Need `a`. |
| `MYRIGHTS` | ✅ | |
| Identifier `anyone` | ✅ | Effective rights are the user's entry plus `anyone`. |
| Identifiers `authenticated`, `anonymous` | ✗ | |
| Negative rights (`-identifier`) | ✗ | |
| Owner rights | ✅ | Always all rights; cannot be changed (`[CANNOT]`). |

Where each right is checked: `l` listing and (un)subscribing shared

and rename in a shared parent, `x` delete and rename, `e` expunge and
close, `t` and `e` move and replace source, `a` ACL commands and the
IMAPSieve script entry.

### Sharing

Other users' folders appear as separate accounts named after the owner,
public folders as the account `~public`. JMAP rights map to IMAP ACL
rights (`mayReadItems` = `l r`, `mayAddItems` = `i`, `mayRemoveItems`
= `t e`, `maySetSeen` = `s`, `maySetKeywords` = `w`,
`mayRename`/`mayDelete` = `x`, `mayCreateChild` = `k`, `mayShare` =
`a`). Shared accounts are listed whether or not the user subscribed to
them, a deviation from RFC 9670 §1.4. Bounds: `jmap.max_shared_accounts`
(default 64), `jmap.max_shared_mailboxes` (default 1000),
`jmap.max_principals` (default 1000), at most
`jmap.max_principal_lookups` (default 5) backend lookups per request and
`jmap.principal_miss_per_minute` (default 30) misses per account.

| IMAPSieve `redirect` and `notify` | ⚙ | Same relay. |
| JMAP EmailSubmission | ⚙ | Separate `jmap.submission.*` relay. By default it names the user with Postfix `XCLIENT LOGIN=…` (`jmap.submission.xclient`; `xclient_addr` adds `ADDR=`) instead of `AUTH`. With `xclient: false` it logs in with `jmap.submission.user`/`password`, and the sender check (`check_sender`) is mandatory. |
| STARTTLS (RFC 3207) / implicit TLS | ✅ | STARTTLS is used whenever the relay offers it; `smtp.starttls` (default on) makes it mandatory. `smtp.tls` for implicit TLS (port 465). TLS 1.2 minimum. |
| `AUTH PLAIN` (RFC 4954) to the relay | ✅ | `smtp.user`, `smtp.password[_file]`; only sent over TLS or to localhost. |
| `8BITMIME`, `SMTPUTF8` on `MAIL FROM` | ✅ | When the relay offers them. |
| DSN parameters | ✗ | RFC 3461 `NOTIFY`/`RET`/`ENVID` are not sent. |

| Feature | Notes |

| Backend | `server.auth_backend`: `nauthilus` (the operational profile) or `static` (code default, a test user list from `server.users`). Nauthilus is reached over gRPC `AuthService` (`nauthilus.transport`, default `grpc`) or its HTTP JSON API. |

| Temporary failure | Reported as unavailable (`[UNAVAILABLE]`, `[SYS/TEMP]`, `451`, HTTP 503), never as a wrong password. |

## Transport: TLS, PROXY protocol, listeners

| Feature | Notes |
|---|---|
| TLS version | 1.2 minimum, server and client side. |
| Certificate reload | The pair is re-checked on the first handshake after `tls.reload_seconds` (default 60; 0 loads once) and reloaded when the files changed; a pair that does not load keeps the old one. |
| Implicit TLS | IMAPS and POP3S (RFC 8314), only when a certificate is configured. Not for LMTP and ManageSieve. |
| PROXY protocol | HAProxy v1 and v2 on IMAP, IMAPS, POP3, POP3S, LMTP, ManageSieve and JMAP, accepted only from `server.proxy_protocol_trusted_cidrs`; 5 s header timeout; applied before TLS. Not on the metrics or admin listeners. |
| Graceful shutdown | Readiness goes red; after a short pause IMAP clients get `BYE`, POP3 clients get `-ERR [SYS/TEMP]` at the end, and sessions have up to `server.drain_seconds` (default 20) to finish. LMTP and ManageSieve listeners close at once. |
| Memory budget | `server.memory_budget_bytes` (default 256 MiB) bounds message buffers across all protocols. |

## Mail store features

### Storage

| Feature | Notes |
|---|---|
| Backend | Ceph RADOS directly: an index pool (omap) and a data pool (may be erasure coded); one RADOS namespace per user. |
| Messages | Immutable blobs in chunks of `ceph.chunk_size` (default 4 MiB), shared by `COPY`; reference counts. No compression or encryption at rest. |
| Consistency | Compare-and-swap on object versions, delivery intents, repair jobs; see [RADOS storage](architecture/storage.md). |
| Credentials | `ceph.key`, or without it the Rook client secret (`rook.namespace`, `rook.client_secret`); the key is re-read every `server.key_poll_seconds` (default 60), and a rotated key is picked up without a restart. |
| Several replicas | Sessions are process-local; all durable state is in RADOS. |

### Full-text search

| Feature | Notes |
|---|---|
| Fields | Subject, From/Sender/Reply-To, To/Cc/Bcc (every value), all header names and values (RFC 2047 in any WHATWG charset, raw 8-bit text in `fts.fallback_charset`), `text/*` parts converted to UTF-8 (the `<meta>` charset for HTML; UTF-8 under a single-byte label is kept as UTF-8), the visible text of HTML parts (`fts.html`: `text`, the default, `raw` or `skip`), the file names of all parts (RFC 2231, RFC 2047), header and text of attached messages; up to 4 MiB of text per message. |
| Words | Unicode letters and digits, 2–40 characters, lower-cased; longer words as their first 40 characters and overlapping 40-character windows (with marker terms beyond). |
| Stemming | Snowball English and German, always both. |
| Substrings | Trigram dictionary. |
| Header store | The decoded header text of every message (DEFLATE, up to 64 KiB), so that header keys are checked without reading messages. |
| IMAP matching | Substrings (RFC 9051); the index is a candidate pre-filter per key and part, candidates are verified in parallel (`fts.verify_parallel`); `fts.imap_search: word` for word semantics. The index version marker is set by `fts_rebuild` (and on a fresh index); without it the index is not used. See [SEARCH](#search-sort-and-thread). |
| Not supported | Attachment content, CJK segmentation, other languages, `SEARCH=FUZZY`, MIME part header fields other than file names. |
