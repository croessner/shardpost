# ShardPost 0.40.0: batch over all accounts, partitioned scrub, IMAP watch hub (scaling stage R2b)

Date: 2026-10-01

## Change

Fourth stage of the plan to run ShardPost with millions of accounts.

- **Batch over all accounts:** one job (`batch`) runs `index_check`,
  `scrub`, `fts_rebuild` or `attachment_backfill` over the account
  directory, page by page with a checkpoint, bounded parallelism and a
  bounded report; `shardpostctl plan -all <kind>`. Clients need the new
  permission `all_accounts` (the Unix socket always has it).
- **Scrub as a batch with skip-if-idle:** an account whose change counter
  and registry did not change since its last complete scrub, with no
  open candidates, intents or findings, is skipped; every account is
  scrubbed at least every `scrub.interval_days` (7). The nightly CronJob
  now runs `shardpost scrub --batch`, which only submits the batch; the
  servers' job runners carry it out. Plain `shardpost scrub` reads the
  account directory instead of listing the pool.
- **Accounts API:** `GET /admin/v1/accounts`, `shardpostctl account list`.
- **IMAP watch hub:** one RADOS watch per object and process, shared by
  all sessions; NOTIFY follows the account object and reads the change
  log instead of one watch per mailbox, with a periodic look every 60 s;
  `server.imap_max_watches` caps watches per connection (one kept for
  IDLE). A refused `NOTIFY SET` keeps the earlier state.

## Review

Three review rounds by a second model. Fixed among others: NOTIFY could
miss a change until the next one when the account log held an entry
back (now a periodic look), a refused `NOTIFY SET` dropped the earlier
state, a gap between a foreign SELECT and its follow, a race in which
two submitters of the nightly batch both kept theirs.

## Rollout

1. 0.40.0 rolled out; no error in the logs.
2. `hack/r2b-smoke.sh`: account list paging (33 accounts), `index_check`
   over all accounts, two batch scrubs — the second skipped 32 of 33
   accounts.
3. Scrub CronJob switched to `scrub --batch` (with an active deadline of
   10 minutes); a manual run submitted the batch, and the servers
   skipped all 33 accounts as unchanged.
4. imaptest: 72 groups, 0 failed, 8 skipped; base 0/460, extensions
   0/272.
