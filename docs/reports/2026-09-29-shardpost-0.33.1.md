# ShardPost 0.33.1: the client address in JMAP identity lookups

Date: 2026-09-29

## Change

`Identity/get` and the sender check of `EmailSubmission` resolve the
account's addresses through the identity lookup of the authentication
backend (Nauthilus `LookupIdentity`). They sent that lookup without the
client's address, although the JMAP session knows it. Nauthilus then saw a
lookup with no client context at all:

- in production the gRPC peer (the local Doppelgaenger sidecar on the
  loopback address) stood in for the client and the lookup passed;
- the shadow instance, which receives the same request mirrored from the
  production pod, saw that pod's address, evaluated GeoIP on it and
  answered some of these lookups with a temporary failure.

The session now hands its client address to the identity lookup
(`session.clientAddr`), exactly as the principal lookup already did. The
push worker keeps looking up without one; no client is behind its own
lookups.
