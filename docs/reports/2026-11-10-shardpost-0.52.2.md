# ShardPost 0.52.2: rules for new mailbox names

Date: 2026-11-10

## Change

Up to 0.52.1 a new mailbox name was only checked for control characters,
and not the same way everywhere: IMAP refused C0 and C1 controls and the
line and paragraph separators, the admin API only C0 and DEL, and none
of the entry points refused wildcards, backslashes or invisible
characters. IMAP had no length bound at all.

- One rule set, `model.CheckNewMailbox`, now applies at every entry
  point that gives a mailbox a new name: IMAP `CREATE` and `RENAME`,
  JMAP `Mailbox/set`, the admin API (create and rename), a Sieve
  `fileinto` or `:fcc … :create` during delivery, and
  `server.autocreate`.
- Refused in a new name: control characters (C0, DEL, C1, U+2028,
  U+2029), `*` and `%`, `\`, bidirectional embedding, override and
  isolate controls, zero width space, word joiner, invisible operators,
  byte order mark and noncharacters. A level must not be empty, `.` or
  `..`, start or end with white space, or lack a visible character; a
  level is at most 255 bytes, the name at most 1024, and a rename must
  not push a mailbox moved along past 1024 bytes.
- Only new levels are checked. An existing mailbox under a name the
  rules would refuse stays reachable, takes deliveries, is answered as
  existing and can get mailboxes below it. Account import and the
  `mailbox_name_convert` job are not held to the rules.
- The refusal carries the reason: IMAP `NO [CANNOT]`, JMAP
  `invalidProperties`, admin API 400 `bad_request` (`shardpostctl` exit
  64). A refused `fileinto` goes to INBOX; a refused `:fcc` copy is not
  stored.
- `server.autocreate` names are taken as written. One that breaks the
  rules stops the server at start-up; before, leading or trailing
  spaces passed validation and the mailbox was created untrimmed.
- The rules and their reasons are in
  [Protocols: Mailbox names](../protocols.md#mailbox-names).

## Rollout

1. `kubectl diff` on `croessner-nauthilus` showed only the image change
   of `shardpost-server`, `shardpost-push` and the `shardpost-scrub`
   CronJob. The overlay sets no `server.autocreate`, so the default
   folders apply and pass the stricter check.
2. `make deploy`; `shardpost-server` and `shardpost-push` rolled out
   (2/2 each, no restarts).
3. No `ERROR` in the server or push logs after the rollout. From the
   `mailtest` pod (with a PROXY v1 header) IMAP, POP3, LMTP and
   ManageSieve answer with their greetings; the JMAP session resource
   answers 401 without credentials.

## Validation

- `make lint`: 0 issues; `make test-docker` green; `make man` and
  `make check-generate` pass.
- One review round (Fable); its findings are fixed in the change: the
  `:fcc` entry point, existing parent levels, subtree length on rename,
  the reason in every admin refusal, levels of invisible characters
  only, and a test that did not send the joiner it named.
- New tests `TestCheckNewMailboxName`,
  `TestCheckNewMailboxKeepsExistingLevels`, `TestCheckMailboxRename`,
  `TestNewNameRules`, `TestMailboxSetRefusesALongPath`,
