# ShardPost 0.29.0: JMAP Quota and VacationResponse (stage 6a)

Date: 2026-09-27. Status: rolled out, healthy; JMAP on the test endpoint
`jmap.roessner-net.de`.

## What the release contains

- **Quota (RFC 9425, `urn:ietf:params:jmap:quota`)**:
  - One Quota object per limited resource, `octets` and `count`, as IMAP GETQUOTA reports them. An unlimited resource is not listed.
  - `warnLimit` comes from the configured `over` warnings.
  - The state encodes the values, so `Quota/changes` returns real deltas, with `updatedProperties: ["used"]` when only usage moved.
  - `Quota/query` filters and sorts; `Quota/queryChanges` answers `cannotCalculateChanges`.
  - Quota types are named `Email`, as in the JMAP registry; a filter for `Mail` also matches.
- **VacationResponse (RFC 8621 section 8)**:
  - Offered when the server can send vacation replies (`smtp.addr`).
  - The setting lives in the account metadata `/private/vendor/shardpost/jmap/vacation` and is the only source at delivery.
  - Delivery builds a Sieve vacation from it and runs it after the active script, only when that script produced no vacation and the message is kept.
  - A Roundcube vacation in the active script therefore wins, and user scripts are never edited.
  - A generated copy `jmap-vacation` is written for display in ManageSieve clients. Nobody can store, rename, delete, activate, import or include it, and export, restore and migrate skip it.
  - Sets are compare-and-swap on the metadata entry (`SwapMetadata`).
  - The reply's handle follows the settings, so a changed text answers a sender again within the period.
- **Server-managed metadata**: IMAP SETMETADATA and the admin import refuse entries under `/private/vendor/shardpost/jmap/`.

## Review

Two Fable rounds.

The first found no blocker. It asked for:
- the metadata as the delivery source, instead of executing the stored copy (a non-active import entry could otherwise have replaced it)
- a compile check before storing
- the guard on server-managed metadata
- an atomic set
- `isEnabled: null` refused
- documentation of subject truncation, the handle and aliases
- canonical quota states
- end-to-end tests

The second confirmed these and found that a user script could still `include` the display copy, and that a restore of an archive naming it active would fail. Both are fixed in `92b12dd`.

Known limits, documented:
- Mail that is discarded or only forwarded gets no reply, as with every Sieve vacation.
- JMAP cannot set `:addresses`, so mail to an alias not in To/Cc is not answered.
- Quota and VacationResponse are not pushed.
- An account export does not carry server metadata, and with it the JMAP identities and the vacation setting (pre-existing).
