# ShardPost 0.35.0: a dictionary with one key per trigram and term

Date: 2026-09-30

## Change

The substring dictionary of the full-text index kept, per trigram, the
list of all terms that contain it as one omap value (`ftsd/<nn>`), read
and rewritten whole for every new term. The
[0.34.5 report](2026-09-30-shardpost-0.34.5.md) has the measurements:
340 MiB of values for an account of 20000 messages, five messages a
second on import, and a server container killed for memory.

The dictionary is now `ftst/<nnn>`: 256 objects with one key per trigram
and term and an empty value, written without reading and without a
version check. A substring query scans the key ranges of the token's
trigrams. The layout and what it means for searches in header fields is
described in [storage](../architecture/storage.md#notifications-and-search).

The old layout is read as long as its objects exist. The job
`fts_dict_convert` writes the dictionary again from the posting lists
and removes them; `fts_rebuild` does it from the messages.

## Review

A review by a second model found no defect in the search path. Changed
after it:

| Finding | Resolution |
| --- | --- |
| `fts_dict_convert` takes no lock and could write into an account that a purge or a rebuild holds | It stops when an import or another job locks the account |
| Every substring lookup kept reading the sixteen objects of the old layout, converted or not | Looked up once per view; a converted account skips them |
| A delivery whose indexing failed halfway left postings and part of the dictionary keys behind | It takes back what it indexed |
| Comments and docs said the old layout was written "until 0.34.5" | 0.34.6 |
| The bound of the prefix lookup in header terms was not documented | Documented |

Left as it is: the unit tests of the key-range scan do not run against a
store (the store tests have none to talk to); the scan was exercised by
the live test below instead.

## Validation

- `make lint`: 0 issues; `make test-docker`: green; `make man`,
  `make check-generate`: clean.
- Live, release candidate, namespace `importtest`: the account
  `de10000@srvint.net` (36076 messages, 1.7 GB) imported in 15m53s, all
  39 mailboxes verified — 38 messages a second where 0.34.6 managed five
  — with a resident size between 300 MiB and 420 MiB.
- Searches on that copy, INBOX of 8319 messages: `SUBJECT rechnung` 46
  and `SUBJECT echnun` 46; `BODY dovecot` 161 and `BODY oveco` 161;
  `FROM roessner` 855 and `FROM oessne` 855; a word that does not occur
  0. The subject and body searches answer in about 50 ms. The address
  search took ten seconds for its 855 hits; that was not compared with
  0.34.6.
- After the rollout `fts_dict_convert` ran for the accounts in service
  and for `~public`, and `fts_rebuild` for `de10000@srvint.net`, whose
  index an interrupted rebuild of 0.34.6 had left incomplete.
- Image `docker.io/chrroessner/shardpost:0.35.0@sha256:047a07d9163fb2259fdaef77c0a29dfb6396a1293cb6472acdb95afcb20252c5`.
