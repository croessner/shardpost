# ShardPost 0.47.0: system pool routing (stage B11a)

Date: 2026-10-02

## Change

First stage of block B11 (plan `temp/12-system-pool.md`, final after
four review rounds and two short checks), prepared for the target
environment of hundreds of OSDs and a million accounts. Nothing moves
yet: with `ceph.system_pool` empty a server behaves as before.

- **Routing:** `ceph.system_pool` places the store's own namespaces
  (`~admin`, `~accounts`, `~learning`, `~server`) in a replicated pool
  of their own; one routing point decides per namespace. The sweep's
  state stays in the index pool.
- **Fence and mark:** a fence in the index pool and a mark in the
  system pool, compared by pool id and fsid, say where the system data
  lives. A server refuses to start against a placement it reads as
  wrong ("run shardpost system init" / "migrate" / inconsistent);
  servers and the push worker re-check every minute and end only on a
  contradiction actually read, never on a read error.
- **Init and lease:** `Store.InitSystem` (the `shardpost system`
  commands follow in B11b) and the tool lease on the fence: one writer
  per process, a 90 s validity window from the send time of the last
  renewal, takeover only after three minutes of an unchanged epoch on
  the taker's own clock.
- **Registrations with roles:** push, scrub, sweep and backfill
  register besides the servers, with start and stop time;
  `shardpostctl server list`, `GET /admin/v1/servers`.
- **Hotspots for many pods:** a server without the learning lease
  retries every 20 s (jitter) instead of every second;
  `imapsieve.learning.index` defaults to `read` (falls back to `write`
  without the backfill marker); `~server` METADATA is cached for 30 s
  per process; new job and plan heads get 16 shards, the layout 3 list
  256; `ceph.client_options` for the objecter limits and the gauge
  `imapceph_rados_inflight_ops`.
- **Bench:** `--system-pool` with its own pool; the bench never takes
  the production system pool.
- **Deploy:** the pool `shardpost-system` (replicated 3, on the rgw
  OSDs like the index pool) and its caps; the manifests set
  `CEPH_SYSTEM_POOL` empty until the cutover.

## Review

One review round by a second model on the code (after the design
rounds): a lease that rewrote an existing fence (harmless now, fatal for
the later commands), a server that refused to start on a placement read
error, a lease kept after an error, no immediate refusal of a foreign
lease holder, missing clock-driven lease tests, and documentation of the
environment override; all fixed.
