# ShardPost 0.35.2: protocol fixes from the documentation audit

Date: 2026-10-01

## Change

Writing [Protocols, features and RFCs](../protocols.md) meant checking
every advertised capability against the code. Most deviations found
that way are documented there; the following were defects and are
fixed:

- The master-user password is compared in constant time.
- IMAP `$` (RFC 5182, SEARCHRES) matched nothing in `UID EXPUNGE $`,
  in the `UID $` search key and in `UID FETCH … (VANISHED)`; it now
  stands for the saved result everywhere a UID set is taken.
- `REPLACE … CATENATE` answered every failure with `[BADURL]`; an
  oversized result is now `[TOOBIG]` and a syntax error `BAD`, as for
  `APPEND`.
- NOTIFY's `[BADEVENT]` lists the supported events (RFC 5465 §5).
- ManageSieve `NOOP "tag"` answers `OK (TAG "tag")` (RFC 5804 §2.13),
  and the capability lists `NOTIFY "mailto"` (RFC 5804 §1.7).
- JMAP `EmailSubmission/query` evaluates `AND`/`OR`/`NOT` and refuses
  unknown conditions, operators and invalid dates with
  `unsupportedFilter` instead of ignoring them.
