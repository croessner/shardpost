# ShardPost 0.44.0: fewer full-text reads per delivery (stage B14a)

Date: 2026-10-02

## Change

First stage of block B14 (full-text write amplification, plan
`temp/11-fts-write-amplification.md`), without a format change and
freely reversible:

- **One read per posting shard:** the check for posting lists in the
  old GUID format runs on the read the compare-and-swap does anyway;
  before, every shard was read twice.
- **No extra read for the id map:** whether an account's index is
  fresh is decided inside the id map's compare-and-swap.
- **Backoff on lost rounds:** a lost omap compare-and-swap waits a
  random 1–10 ms × attempt before the next round;
  `imapceph_rados_cas_retries_total` has a `class` label (fixed set:
  `fts`, `ftsmap`, `registry`, `mbox`, `account`, `index`, `msg`,
  `other`).
- **Bench probes:** `shardpost bench measure --contention P` (P
  deliveries at a time into one account), `--search K` (fixed query
  set, cost and a result fingerprint over message GUIDs) and
  `--expunge N`.

## Review

Two review rounds by a second model for the code, five rounds for the
design of the stage that follows (B14b). Fixed among others: a dead
retry path, a backoff after the last round, documentation of which
objects go through which compare-and-swap, labels of short search
words.

## Rollout

1. 0.44.0 rolled out (server and push); no error or warning in the
   logs.
2. imaptest: 72 groups, 0 failed, 8 skipped; base 0/460, extensions
   0/272. `hack/r3-smoke.sh` and `hack/r5-smoke.sh` passed.
   `hack/auth-smoke.sh` failed once while the old pods were still
   draining (too few cache hits counted) and passed when repeated
   right after.
3. Bench (`shardpost bench measure` on the R4 bench pools, 20 probe
   accounts of 50–70 messages):

| Measurement | 0.43.0 | 0.44.0 |
|---|---|---|
| Operations per delivery | 245.6 | 226.4 (28 reads, 198.4 writes) |
| `fts` per delivery | 32 R + 16 W | 16 R + 16 W |
| `ftsmap` per delivery | 2 R + 1 W | 1 R + 1 W |
| Delivery latency, one at a time | p50 289 ms, p99 524 ms | p50 295 ms, p99 590 ms |
| Four at a time into one account | – | 7.3/s, p50 524 ms, 0.56 CAS retries per delivery (`fts` 421, `account` 230, `registry` 223 of 901) |
| EXPUNGE of one message | – | 204 operations (`ftst` 148 writes), p50 301 ms |
| Search query | – | 38.4 reads, p50 35 ms, p99 134 ms |

The trigram dictionary (`ftst`, about 150–175 writes per delivery and
per expunge) remains the cost B14b removes.
