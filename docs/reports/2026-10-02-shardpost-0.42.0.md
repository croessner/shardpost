# ShardPost 0.42.0: intents, scrub and purge without per-account listings, sweep (scaling stage R3)

Date: 2026-10-02

## Change

Fifth stage of the plan to run ShardPost with millions of accounts.

- **Intents:** every write that may leave an unnamed object behind
  names it first: new blobs (`bi:`), import steps (`bimp:`), JMAP
  uploads (`up:`, with an expiry queue and worker), mailbox creations
  (`ci:`), message removals (`r:` per UID on shard 0), mailbox deletions
  (tombstone `dm:` with the UID range) and public `\Seen` marks (`ps:`).
  DELETE retires the mailbox header first, so a delivery that looked the
  mailbox up before cannot allocate a UID in it any more.
- **Scrub from intents:** `scrub.orphan_source` `listing`, `shadow`
  (default) or `intents`. In `shadow` the scrub lists and repairs as
  before, works out what the intents name and reports differences
  (`imapceph_scrub_shadow_differences_total{kind}`). The scrub never
  releases a blob again on account of an intent; it recounts.
- **Purge from the data model:** the purge enumerates an account's
  objects instead of listing the pools; `purge.listing` (default true)
  keeps the listing as fallback and counts what the model does not name
  (`imapceph_scrub_purge_unnamed_objects_total`). The purge now also
  removes the account's JMAP records in the admin store and records the
  account in `ix.purged` for the sweep.
- **Sweep:** `shardpost scrub --sweep [--repair]` walks both pools once,
  resumable, and finds what no model names (debris from before 0.42.0,
  never-scrubbed accounts). It deletes only in namespaces being purged
  or recorded as purged without directory entry, never in a namespace
  with an active entry, and only objects older than both the grace and
  the moment it read the namespace (less a clock margin), at the version
  it read.
- **Defaults are the safe ones:** listing remains authoritative. The
  switch to `orphan_source: intents` and `purge.listing: false` is
  described in `docs/operations/README.md` ("Scrub without listings").
- **Tests:** `make test-docker` now starts a single-node Ceph cluster, so
  the store code runs against real RADOS in the tests.

Hot-path cost (OSD ops, 0.41.0 → 0.42.0): LMTP delivery +0.7 reads and
+1 write, EXPUNGE +1 write, APPEND unchanged, CREATE+DELETE +2/+3, JMAP
upload +1.2/+2.2.

## Review

An internal review round and six review rounds by a second model, the
last without a blocking finding. Fixed among others: two
double-decrement windows (EXPUNGE against the scrub's recount, DELETE
releasing entries a concurrent EXPUNGE had already released), a sweep
that would have removed Sieve-only accounts and re-created accounts
whose registry was lost, an import intent too large for an omap value,
colliding fallback GUIDs within one import step that could cost a blob,
a panic in DELETE without shard 0, and the sweep's time line against
second-resolution mtimes from the writers' clocks.

## Rollout

1. 0.42.0 rolled out (server and push); no error in the logs.
2. `hack/r3-smoke.sh` (throwaway account): temporary mailbox created,
   three messages appended, one expunged, mailbox deleted; scrub in
   shadow mode without differences and without open intents.
3. Nightly batch scrub started by hand: 33 accounts, 5 scrubbed, 28
   skipped as idle, no finding, no shadow difference.
4. imaptest: 72 groups, 0 failed, 8 skipped; base 0/460, extensions
   0/272. The smoke scrub after it was again without difference.

Purge and sweep were not run on the cluster (see the header of
`hack/r3-smoke.sh`); they are covered by the store tests.
