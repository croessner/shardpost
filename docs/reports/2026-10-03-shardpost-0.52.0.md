# ShardPost 0.52.0: push partitions, job runner pods, online quota recount, mailbox lock (stages B16, B17, B18)

Date: 2026-10-03

## Change

Three stages ship together, each behind its own switch; without the
switches the servers behave as in 0.51.0.

- **B18a, JMAP push partitions.** The push worker no longer runs as one
  holder of one lease: the push subscriptions are split into 64
  partitions (the shards of the push index), each with a lease of its
  own, shared by any number of push pods through a membership object
  with heartbeats, rebalancing and an orderly hand-over in waves at
  shutdown. The delivery state per subscription is an acknowledgement
  with an epoch instead of an in-memory backlog, so a hand-over loses no
  notification (0.51.0 could lose one on every rollout) and repeats at
  most one. Planned hand-over ≤ 10 s, a crashed pod ≤ 44.5 s. The 0.51.0
  lease record stays occupied as a marker while new pods run. croessner
  runs two push pods (rolling update, disruption budget, grace 45 s).
- **B18b, job runner pods.** `shardpost runner` runs the background
  workers (jobs, expiry, `fts_due`, upload expiry, delayed submission,
  learning) without listeners; `WORKERS_RUN=false` makes servers
  front-ends (components `deploy/components/runner` and
  `runner-frontends`, applied in two steps). The learning worker runs
  `imapsieve.learning.concurrency` jobs at once, one account at a time
  in due order. croessner keeps its two combined pods.
- **B16, online quota recount.** `quota_recalc` runs without the account
  lock: the usage writers capture their changes for a run (marked
  arrivals, recorded departures, a gate for MOVE between counted
  mailboxes), the run lists the mailboxes, waits for the operations that
  started before it and switches with one compare-and-swap. Cluster mark
  `quota/online`. Cost: one extra write per release (expunge, MOVE to an
  ignored mailbox), one extra read per MOVE between counted mailboxes.
- **B17, mailbox lock.** `mailbox_delete` locks only the mailboxes it
  removes: writes into them are refused (`NO [UNAVAILABLE]`, JMAP
  `forbidden` / `invalidProperties`), a Sieve `fileinto` lands in INBOX,
  sessions that have one selected get `BYE`; everything else in the
  account carries on. Cluster mark `mailbox/lock`.

Plans: `temp/15-partitions-runners.md` (Fassung 6),
`temp/16-quota-online-mailbox-lock.md` (Fassung 5). Implementation in
two branches, one code review each (Fable), all findings fixed: B18b
nine (among them an empty `CEPH_SYSTEM_POOL` in the runner manifest that
overrode the configmap, and paging in the learning queue), B18a ten
(among them a use-after-destroy in the lease retake path and a shutdown
race of the members channel), B16/B17 three (among them the run tag on
removal intents, without which a message delivered and removed during a
run could be counted twice).

Also: the Sieve CPU budget test builds its script itself instead of
reading the untracked Pigeonhole corpus; `shardpost-load` names its load
and corpus mode flags apart.
