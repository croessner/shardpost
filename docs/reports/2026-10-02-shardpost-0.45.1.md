# ShardPost 0.45.1: layout 3 switched on, JMAP answer for locked accounts

Date: 2026-10-02

## Change

- **JMAP:** an account under an import or maintenance lock (an import, a
  purge, a full-text conversion) is answered 503 with `Retry-After`
  (`jmap.retry_after`) and logged at info level. Before, the 503 had no
  `Retry-After` and every request logged an error.
- **Runbook** (`docs/operations/README.md`, "Full-text layout 3"): the
  measured duration of a conversion and what clients see during it.

## Layout 3 switched on (croessner, 0.45.0)

1. Both servers registered with 0.45.0 and `fts_layout3`;
   `shardpostctl fts layout3 enable -pods 2` set the cluster mark.
2. The throwaway account `rbdpoc2@exampleserver.de` converted first
   (layout 3, S/D/H 1/1/1); imaptest, `hack/r3-smoke.sh` and
   `hack/r5-smoke.sh` passed on it.
3. `fts.layout: 3` in the overlay: new indexes are created in layout 3.
4. `shardpostctl plan -all -layout 3 fts_layout`: 33 accounts, 33 done,
   none failed, in about six minutes (`jobs.batch_parallel` 2).
   `shardpostctl fts layout3 list` names all 33.
5. The largest account (36 246 messages, 1.8 GB, now S/D/H 4/16/1) was
   locked for about 3.5 minutes: deliveries were deferred (LMTP 451),
   two IMAP logins were refused, and JMAP answered 503 without
   `Retry-After` and logged an error per request — fixed in this
   release. The bench accounts (50–70 messages) took about 3.5 s each;
   the conversion was run in the afternoon, not at the quiet time the
   runbook recommends.
