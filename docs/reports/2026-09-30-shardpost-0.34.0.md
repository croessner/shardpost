# ShardPost 0.34.0: global Sieve scripts and the import of a public namespace

Date: 2026-09-30

## Change

Two gaps stood between a Dovecot installation with public folders and a
move of its accounts to ShardPost.

- **Global Sieve scripts.** `sieve.before_dir` and `sieve.after_dir` hold
  scripts that run for every delivery around the account's active
  script, the way Pigeonhole runs `sieve_before` and `sieve_after`
  ([configuration](../configuration.md#global-sieve-scripts)). The keep
  of one script is handed to the next together with its flags; a script
  that fails is skipped as if it had kept the message. `sieve check`
  runs the same sequence.
- **Public namespace import.** `shardpostctl migrate -source-namespace`
  imports a namespace of the source other than the personal one into
  `~public`, keeping UIDVALIDITY, UIDs, MODSEQ and flags; `-readers`
  carries each named account's own `\Seen` and subscriptions over
  ([admin API](../admin-api.md#importing-a-public-namespace)).
- **Locked namespaces over IMAP.** A command that needs a namespace under
  an import or maintenance lock is answered `NO [UNAVAILABLE]` (it was
  `NO [SERVERBUG]` with an error log line), and a session that had such
  a namespace open before the lock notices it within the lock check
  interval.

The `croessner-nauthilus` overlay mounts one after script,
`sieve-after/50-public-folders.sieve`: the `sieve_after` script of the
mailstack (`public-mls.sieve`) with its targets below `Public/`.

## Review

Three review rounds by a second model. What they found and what became
of it:

| Finding | Resolution |
| --- | --- |
| Flags of a kept message were lost when a later script kept it too | The keep is handed on with its flags; they are what the next script's flag variable starts with, in the spelling the script used, so `removeflag` still works |
| `NO [SERVERBUG]` for every `LIST` while `~public` is locked; sessions with the namespace already open did not notice the lock | `NO [UNAVAILABLE]`; cached views are re-checked |
| A later import run resets a reader's `\Seen` to the source and leaves HIGHESTMODSEQ ahead of the source | Documented: import only into folders not in use here yet, last run before clients arrive |
| A reader that can list but not open a folder failed the run | Skipped with a warning (only a `NO` to STATUS or EXAMINE counts) |
| A `BAD` to the flag fetch was read as "nothing seen" | Only for a mailbox STATUS reports as empty |
| One unreadable file cost every script of a directory | The readable ones run; startup and `config check` stay strict |
| Prune removed the folder the target prefix names | It stays |
| Base deployment set the two directory variables to "" (which wins over a configuration file) | Removed from the base |
