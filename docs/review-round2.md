**The fixes are not yet sufficient to release production mail stores.** In particular, risks of data loss remain with higher shards and with the scrubber. The new pending and rollback logic creates additional error paths.

Static comparison against `docs/review-round1.md`, excluding `vendor/`. The tests for `internal/imapproto`, `internal/pop3proto`, `internal/auth` and `internal/fts` passed. Ceph integration, crash recovery and the race detector were not run. "Fixed" therefore refers to the static finding status.

**New findings, respectively concrete follow-up bugs of the fixes**

1. **High – A commit error can leave a visible index entry without a blob.**  
   `link` writes the higher shard and then calls `commitPending` (`internal/cephstore/user.go:990–994`). If this commit fails, `Deliver` treats the entire link as failed and deletes the blob (`:947–951`). The index entry that was already written remains. With COPY, the additional reference is accordingly subtracted again (`:1233–1236`), although the target already references it.

2. **High – Pending does not serialize changes to higher shards.**  
   `casHeader` does not take pending changes into account (`internal/cephstore/user.go:605–610`). Example: STORE A reserves ModSeq 10 but does not yet write the shard. STORE B reads the old flags there and reserves ModSeq 11. The version comparison in `writeEntries` only protects against lower ModSeqs (`:891`), not against the already incorrectly computed result. After a deletion, even that comparison partner is missing: a late STORE can re-create the removed entry.

3. **Medium – An aborted pending delivery can block the incremental poll permanently.**  
   After 30 seconds, pending is ignored without verification (`internal/cephstore/user.go:751`). If the announced UID is permanently missing, `poll` returns without watermark progress or a reload (`internal/imapproto/selected.go:73–77`). Every further poll processes the same missing UID; later changes stay stuck until some other reload or log loss occurs. Conversely, the deadline does not protect against a merely slow writer.

4. **High – MULTIAPPEND widens the memory DoS to a single connection.**  
   The fix collects all message strings in `parts` (`internal/imapproto/mailbox.go:399–427`). Each literal only has its own limit (`wire.go:282`); the sum is unbounded. The store budget is only requested during the subsequent delivery. A single valid MULTIAPPEND input can therefore exhaust the process memory.

5. **Medium – The deadline fix overlooks automatic buffer flushes.**  
   `beforeFlush` runs exclusively in `writer.flush()` (`internal/imapproto/wire.go:318`). `WriteString`, `Fprintf` and especially `literalOut` can already write to the socket themselves (`:325–329`, `:388–390`). After a longer idle period, a FETCH body larger than the buffer size, for instance, fails on the old deadline; renewing it later does not clear the stored writer error.

6. **Medium – The new script name limit can make RENAMESCRIPT fail after a change has already been made.**  
   `RenameScript` does not check the length of the target name itself and first moves the content (`internal/cephstore/scripts.go:128–133`). Only the subsequent activation checks the limit (`:141`, `:102`). On a direct store call with an overlong target, the old script has then already been removed while `active` still points to it; `ActiveScript` interprets that as no filter (`:69–71`). The ManageSieve name check bounds the immediate protocol reachability.

7. **Medium – The new header re-check discards valid hits in folded headers.**  
   The newly retained criteria run through `textMatch` (`internal/imapproto/search.go:516–517`). There, every physical header line is checked separately (`:660–661`). With `X-Special: erster Teil\r\n needle`, the continuation line belongs to the same field but is not taken into account. Likewise, read errors are swallowed as "no hit" (`:643–645`), so SEARCH can still return incomplete results successfully.

Finding **31** remains, as requested, outside the re-check and stays as a roadmap item.
